# JISUNG 92 디자인 시스템

## 1. 문서 목적

이 문서는 JISUNG 92에 새로운 페이지나 도구를 추가하고 기존 화면을 수정할 때 따라야 할 디자인 기준을 정리한다.

JISUNG 92의 디자인은 **Windows 9x 계열의 레트로 데스크톱 환경**을 바탕으로 한다. 다만 레트로 표현 자체보다 가독성과 사용성을 우선한다.

> 핵심 원칙: 바깥은 JISUNG 92답게, 페이지와 도구 안쪽은 각 기능에 맞게 설계한다.

---

## 2. 디자인 구조

JISUNG 92의 화면은 다음 두 영역으로 구분한다.

### 2.1 공통 데스크톱 영역

모든 페이지와 도구에서 JISUNG 92의 정체성을 보여주는 영역이다. 현재 적용된 공통 스타일을 기준으로 유지한다.

- 짙은 청록색 바탕화면과 격자무늬
- 화면 위의 미세한 CRT 주사선 효과
- Windows 9x 형태의 프로그램 창
- 파란색 계열 제목 표시줄
- 하단 작업표시줄과 시계
- 바탕화면 바로가기 아이콘
- 검은색 외곽선과 오른쪽 아래로 어긋난 단색 그림자
- 홈으로 돌아갈 수 있는 메뉴 또는 닫기 버튼

공통 데스크톱 요소는 `assets/css/desktop.css`와 `assets/js/desktop.js`를 우선 사용한다. 개별 도구에서 같은 요소를 별도로 다시 만들거나 서로 다른 형태로 변경하지 않는다.

### 2.2 앱 작업 영역

프로그램 창 안쪽의 실제 기능 영역이다. 앱의 목적에 따라 구성을 다르게 할 수 있다.

- 검증기·계산기: 입력, 점검 결과, 다운로드가 잘 보이는 업무도구형 구성
- 생성기: 설정과 미리보기를 함께 확인할 수 있는 구성
- 선택형 앱: 탐색과 선택 과정이 즐거운 친근한 구성

모든 도구의 내부 화면을 똑같이 만들 필요는 없다. 다만 색상, 테두리, 버튼 반응 등 일부 공통 요소를 사용해 JISUNG 92에 속한 도구라는 인상을 유지한다.

## 3. 색상

### 3.1 공통 색상

| 용도 | 변수 또는 색상 | 사용 기준 |
| --- | --- | --- |
| 바탕화면 | `#164a43` | 전체 데스크톱 배경 |
| 기본 화면 | `#fff8df` | 프로그램 창의 기본 배경 |
| 글자·외곽선 | `#191c1b` | 주요 글자, 테두리, 단색 그림자 |
| 강조·선택 | `#ffd84d` | 주요 버튼, 선택 상태, 강조 표식 |
| 성공·사용 가능 | `#92e6c0` | 정상, 사용 가능, 완료 상태 |
| 정보·보조 강조 | `#75bfff` | 아이콘, 정보성 요소 |
| 경고·포인트 | `#ff7897` | 주의가 필요한 요소와 장식 포인트 |
| 비활성·창 버튼 | `#d8d4c7` | 준비 중, 비활성, 시스템형 버튼 |
| 제목 표시줄 | `#082e6f` → `#168da1` | 프로그램 제목 표시줄 그라데이션 |

### 3.2 색상 사용 원칙

- 공통 영역에서는 위 색상을 우선 사용한다.
- 앱 내부에는 기능에 필요한 전용 색상을 추가할 수 있다.
- 전용 색상을 사용하더라도 강조색을 지나치게 늘리지 않는다.
- 상태는 색상만으로 구분하지 않고 반드시 문구를 함께 표시한다.
- 본문과 배경은 충분한 명도 차이를 유지한다.

## 4. 글꼴과 문구

### 4.1 글꼴

- 프로그램명, 제목, 메뉴, 버튼: `Courier New`, `Malgun Gothic`, monospace 순서
- 긴 설명, 안내, 입력값: `Malgun Gothic`, sans-serif 계열 우선
- 한 화면 안에서 장식용 글꼴을 추가하지 않는다.

### 4.2 표기

- 프로그램 제목에는 필요할 경우 `.EXE`를 사용한다.
- 시스템 문구와 짧은 영문 표기는 대문자를 사용할 수 있다.
- 실제 기능명은 자연스러운 한글을 우선한다.
- 버튼명은 실행 결과를 바로 알 수 있게 작성한다.
- 안내 문구는 짧고 직접적으로 작성한다.

---

## 5. 형태와 간격

### 5.1 테두리와 그림자

- 공통 창과 주요 카드의 외곽선은 검은색 `3px`을 기본으로 한다.
- 그림자는 흐린 블러보다 오른쪽 아래로 어긋난 단색 그림자를 우선한다.
- 입력칸과 작은 내부 요소는 `2px` 테두리를 사용할 수 있다.
- 한 화면 안에서 테두리 굵기를 불필요하게 다양화하지 않는다.

### 5.2 모서리

- 공통 창은 직각 또는 최대 `3px`의 약한 둥글기를 사용한다.
- 아이콘과 작은 강조 요소는 최대 `9px`까지 허용한다.
- 일반적인 현대식 대형 라운드 카드 형태는 공통 데스크톱 영역에 사용하지 않는다.

### 5.3 간격

- 기본 간격 단위는 `4px`을 기준으로 한다.
- 자주 사용하는 간격은 `8px`, `12px`, `16px`, `24px`이다.
- 같은 역할의 요소에는 동일한 간격을 적용한다.
- 기능 영역은 장식보다 정보 밀도와 작업 흐름을 우선한다.

---

## 6. 버튼과 입력 요소

### 6.1 버튼

- 기본 버튼은 검은색 외곽선과 단색 그림자를 사용한다.
- 주요 실행 버튼은 노란색, 일반 버튼은 회색 또는 흰색을 우선한다.
- 마우스를 올리면 배경색 또는 위치가 변해 클릭 가능함을 보여준다.
- 누를 때 버튼이 아래로 이동하고 그림자가 줄어드는 반응을 사용한다.
- 같은 화면에서 주요 실행 버튼은 가급적 하나의 위계로 명확히 구분한다.

### 6.2 입력 요소

- 입력칸, 선택상자, 업로드 영역은 라벨을 함께 제공한다.
- 라벨만으로 이해하기 어려운 항목은 도움말이나 툴팁을 제공한다.
- 기본값이 있는 경우 실제로 가장 자주 사용하는 값을 넣는다.
- 오류가 발생하면 문제 원인과 해결 방법을 입력 요소 가까이에 표시한다.

---

## 7. 상태와 피드백

앱은 사용자의 행동에 다음 상태를 명확하게 보여줘야 한다.

- 기본 상태
- 마우스 오버 상태
- 키보드 포커스 상태
- 실행 중 상태
- 성공 상태
- 경고 상태
- 오류 상태
- 비활성 상태
- 결과가 없는 상태

단순히 색만 바꾸지 않고 아이콘, 문구 또는 형태 변화를 함께 사용한다. 다운로드나 복사처럼 결과가 즉시 보이지 않는 기능은 완료 알림을 제공한다.

검은색 배경의 터미널형 안내문은 문구 뒤에 `<span class="cursor"></span>`를 사용해 깜빡이는 커서를 표시한다. 안내 문구가 실행 중, 완료, 오류 등으로 바뀌어도 커서 요소가 유지되도록 구현한다.

---

## 8. 움직임

- 기본 전환시간은 `0.12초`에서 `0.2초` 사이로 한다.
- 마우스 오버 시 요소를 위로 `2px`에서 `3px` 정도 이동할 수 있다.
- 클릭 시 아래로 `2px`에서 `5px` 이동하며 그림자를 줄인다.
- 창 부팅, 앱 목록 전환, 토스트 알림 등 짧은 움직임만 사용한다.
- 반복 애니메이션은 마스코트나 상태 표시처럼 의미가 있는 경우에만 제한적으로 사용한다.
- 업무 입력이나 결과 확인을 방해하는 움직임은 사용하지 않는다.

---

## 9. 화면 구성과 반응형

- 첫 화면에서 앱의 핵심 기능 또는 시작 방법을 바로 확인할 수 있어야 한다.
- 제목과 설명이 실제 작업 영역보다 지나치게 많은 공간을 차지하지 않도록 한다.
- 설정과 결과를 함께 보는 앱은 넓은 화면에서 좌우 배치를 우선 검토한다.
- 작은 화면에서는 한 열로 자연스럽게 전환한다.
- `1920×1080` 데스크톱 환경을 우선하되, 가로 스크롤 없이 모바일에서도 주요 기능을 사용할 수 있어야 한다.
- 모바일에서는 바탕화면 아이콘이나 장식 요소를 숨길 수 있다.
- 고정 작업표시줄에 콘텐츠가 가려지지 않도록 하단 여백을 확보한다.

---

## 10. 접근성과 사용성

- 모든 버튼에는 기능을 알 수 있는 텍스트 또는 접근 가능한 이름을 제공한다.
- 키보드로 주요 기능을 실행할 수 있어야 한다.
- 포커스 상태를 시각적으로 확인할 수 있어야 한다.
- 아이콘만으로 기능을 전달하지 않는다.
- 작은 글씨는 보조 설명에만 사용하고 주요 정보에는 사용하지 않는다.
- 중요한 기능은 마우스를 올려야만 확인할 수 있게 만들지 않는다.

## 11. 새 앱 제작 기준

새로운 앱을 추가할 때 다음 사항을 확인한다.

- [ ] 공통 데스크톱 스타일과 스크립트를 사용했는가?
- [ ] 제목 표시줄에 앱 이름이 표시되는가?
- [ ] 홈으로 돌아가는 방법이 있는가?
- [ ] 첫 화면에서 앱의 용도를 이해할 수 있는가?
- [ ] 핵심 기능이 장식보다 먼저 보이는가?
- [ ] 버튼과 입력 요소의 상태가 명확한가?
- [ ] 성공, 경고, 오류 결과를 문구로 안내하는가?
- [ ] 작업표시줄에 콘텐츠가 가려지지 않는가?
- [ ] 작은 화면에서도 핵심 기능을 사용할 수 있는가?
- [ ] 공식 업무시스템으로 오인할 수 있는 표현이 없는가?

## 12. 변경 원칙

- 현재 공통 데스크톱 디자인을 JISUNG 92의 기준 디자인으로 삼는다.
- 새로운 앱 때문에 공통 스타일을 바꿔야 한다면 기존 앱에 미치는 영향을 먼저 확인한다.
- 앱 하나만을 위한 예외 규칙은 해당 앱 내부에 한정한다.
- 공통으로 반복되는 스타일은 `assets/css/desktop.css` 또는 `assets/css/site.css`에 반영한다.
- 공통 동작은 `assets/js/desktop.js` 또는 `assets/js/site.js`에 반영한다.
- 디자인 규칙을 변경한 경우 이 문서도 함께 갱신한다.
